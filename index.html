Introdução

O que é o Git?

O Git é um sistema de controle de versões distribuído, utilizado para registrar e acompanhar as alterações feitas em arquivos ao longo do tempo.
Ele é muito utilizado no desenvolvimento de software porque permite que programadores acompanhem a evolução de seus projetos, recuperem versões anteriores e trabalhem em funcionalidades diferentes sem precisar manter várias cópias manuais de uma mesma pasta.
Imagine que você está desenvolvendo um site e, ao longo dos dias, altera o HTML, o CSS e o JavaScript. Com o Git, você pode registrar essas alterações e consultar o histórico do projeto.

Exemplo prático

Você está criando um site pessoal:
  • Versão 1: criou a página inicial.
  • Versão 2: adicionou um menu de navegação.
  • Versão 3: criou uma página de contato.
  • Versão 4: corrigiu um erro no layout.
O Git permite registrar esses estados do projeto e entender o que mudou de uma versão para outra.

Qual a diferença de Git e GitHub

Embora os nomes sejam frequentemente utilizados juntos, eles têm funções diferentes.

Git

É o sistema de controle de versões instalado no computador. Ele permite criar commits, comparar alterações, criar branches e manter o histórico de um projeto.

Exemplo: 
                                
                                    git commit -m "Adiciona menu"

GitHub

É uma plataforma online que hospeda repositórios Git e oferece ferramentas para colaboração, como Pull Requests, revisão de código, Issues e gerenciamento de projetos

Exemplo: Publicar um repositório e compartilhar seu link.

Definições de termos

O que é um repositório?

Um repositório, ou repository, é o local onde o Git acompanha os arquivos e mantém o histórico de versões de um projeto.
Existem dois conceitos importantes:

  • Repositório local: fica no computador do usuário.
  • Repositório remoto: fica em um servidor, por exemplo, no GitHub.

Um repositório Git contém informações de controle de versão armazenadas principalmente na pasta oculta .git.
Essa pasta guarda dados importantes para o funcionamento do Git, como o histórico e as referências do projeto. Não é recomendado excluí-la, pois isso remove os metadados necessários para o repositório funcionar corretamente.

O que é um commit?

Um commit é um registro de um conjunto de alterações no histórico do repositório. Cada commit possui um identificador, uma mensagem e informações de autoria e data.
Pense nele como um ponto registrado na evolução do projeto.

O que é uma branch?

Uma branch, ou ramificação, é uma referência móvel para uma linha de desenvolvimento. Ela permite trabalhar em uma funcionalidade sem precisar realizar todo o trabalho diretamente na branch principal.

Primeiros comandos

Os comandos básicos permitem iniciar o controle de versão, acompanhar alterações e salvar pontos importantes do projeto.

git init

Inicializa um novo repositório Git na pasta atual. Após executar o comando, o Git cria uma estrutura interna chamada .git, que armazena o histórico e as informações do repositório.

git status

Mostra o estado atual do repositório, indicando arquivos modificados, arquivos novos e alterações preparadas para commit. É recomendado executar esse comando frequentemente para saber o que será incluído no próximo commit.

git add

Prepara as alterações para serem incluídas em um commit. Essa etapa é conhecida como staging.

  • Para adicionar um arquivo específico: git add index.html
  • Para adicionar todas as alterações rastreadas e os arquivos novos da pasta atual: git add .
O comando git add não cria um commit; ele apenas prepara as alterações selecionadas.

git commit

Registra um ponto no histórico do projeto com as alterações preparadas. A opção -m permite escrever a mensagem do commit diretamente no terminal.
Uma mensagem clara facilita entender o que foi alterado e por quê.

git log

Exibe o histórico de commits do repositório.

  • Para visualizar um histórico resumido: git log --oneline
Cada commit possui um identificador, autor, data e mensagem.

Problemas comuns e boas práticas
Situação Comando Resultado
Retirar arquivo da área de staging git restore --staged arquivo.html Mantém as mudanças no arquivo, mas o retira da preparação.
Descartar alterações locais não preparadas git restore arquivo.html Descarta as mudanças locais desse arquivo.
Criar um commit que desfaz outro git revert HASH Registra um novo commit que reverte as alterações do commit indicado.
Voltar a branch para outro commit git reset Move a referência da branch; o efeito depende da opção utilizada.
Atenção: git restore pode descartar alterações locais definitivamente. Antes de executar comandos destrutivos, confira o estado do repositório e faça uma cópia do que deseja preservar.
